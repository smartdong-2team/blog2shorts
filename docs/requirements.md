# 요구사항 정의서 — Blog to Shorts (가칭)

> 상태: 초안 v0.1 (2026-11-03) · 이 문서의 기능은 **아직 구현되지 않았다.** 현재 구현 범위는 [README](../README.md)의 "현재 구현 상태"를 따른다.

## 1. 프로젝트 개요

블로그 글(URL 또는 본문 텍스트)을 입력하면 AI가 핵심 내용을 분석해 숏폼 대본과 장면을 만들고, 사용자가 장면을 수정한 뒤 9:16 세로형 MP4 영상으로 받아보는 웹서비스 MVP다.

핵심 사용자 흐름:

```
콘텐츠 입력 → AI 대본 생성 → 장면 구성·편집 → TTS·자막 생성 → 영상 합성 → 미리보기·다운로드
```

미니인턴 과제로, 범용 영상 편집기가 아니라 **위 흐름을 하나의 웹 화면에서 끝까지 경험**하게 하는 것이 목적이다.

## 2. 해결하려는 문제

- 블로그 운영자는 이미 써 둔 글을 숏폼(릴스·쇼츠)으로 재가공하고 싶지만, 대본 작성·편집·더빙·자막 작업에 시간이 많이 든다.
- 기존 편집 도구는 학습 비용이 높고, 글 → 영상 변환을 한 번에 해주지 않는다.

## 3. 목표 사용자

- 1차: 자신의 네이버 블로그 글을 숏폼으로 홍보하려는 블로그 운영자 (MVP 검증 대상: `copper567` 블로그)
- 2차: 영상 편집 경험이 적은 소상공인·개인 크리에이터 (본문 직접 입력 경로 사용)

## 4. MVP 범위

| 구분 | 범위 |
|---|---|
| URL 입력 | **네이버 블로그 `copper567` 계정의 글만 지원** (예: `https://blog.naver.com/copper567/224443571088`) |
| 본문 입력 | 어떤 글이든 텍스트로 붙여 넣기 가능 (항상 사용 가능한 대체 경로) |
| 대본 | 30~60초, Hook → 본문 → CTA, 4~6장면 |
| 편집 | 장면별 문구·이미지 변경 (브라우저 상태로 관리, 서버 저장 없음) |
| 출력 | 9:16(1080×1920) MP4, 미리보기 + 다운로드 |
| 사용자 | 로그인 없음, 단일 사용자 데모 |

## 5. 필수 기능 요구사항

### FR-01. 콘텐츠 입력

| ID | 요구사항 |
|---|---|
| FR-01-1 | 사용자는 블로그 URL을 입력할 수 있다. |
| FR-01-2 | 사용자는 블로그 본문을 직접 입력(붙여 넣기)할 수 있다. |
| FR-01-3 | 입력값을 검증한다. URL: 형식·허용 도메인·허용 블로그 ID. 본문: 최소 200자, 최대 20,000자(값은 설정으로 조정). |
| FR-01-4 | URL 입력 시 제목·본문 텍스트·본문 이미지 목록을 추출한다. |
| FR-01-5 | 추출이 불가능한 경우(허용되지 않은 URL, 비공개·삭제 글, 구조 변경, 네트워크 오류) 원인별 오류 메시지를 보여주고 본문 직접 입력을 안내한다. |

허용 URL 규칙 (MVP):
- 호스트: `blog.naver.com`, `m.blog.naver.com`
- 형태: `/{blogId}/{logNo}` 또는 `/PostView.naver?blogId=..&logNo=..`
- `blogId`는 설정값 `NAVER_BLOG_IDS`(기본 `copper567`)에 포함되어야 한다.
- 그 외 모든 URL은 서버가 요청을 보내지 않고 거부한다.

### FR-02. AI 대본 생성

| ID | 요구사항 |
|---|---|
| FR-02-1 | 콘텐츠의 핵심 내용(주제, 핵심 포인트 3~5개)을 분석한다. |
| FR-02-2 | 30~60초 분량의 숏폼 대본을 생성한다 (한국어 기준 내레이션 총 약 150~350자). |
| FR-02-3 | 구조는 Hook(1장면) → 본문(2~4장면) → CTA(1장면)이다. |
| FR-02-4 | 총 4~6개 장면이며 순서가 명시된다. |
| FR-02-5 | 장면마다 내레이션(TTS용)과 자막 문구(화면 표시용, 짧게)를 생성한다. |
| FR-02-6 | 장면마다 추천 이미지(추출된 원본 이미지 중 하나)를 지정한다. |
| FR-02-7 | AI 응답은 정해진 JSON 스키마로 검증하며, 검증 실패 시 재시도 또는 오류를 반환한다. |

### FR-03. 장면 구성 및 편집

| ID | 요구사항 |
|---|---|
| FR-03-1 | 장면 목록을 순서대로 보여준다 (역할 Hook/Body/CTA, 내레이션, 자막, 이미지). |
| FR-03-2 | 장면별 내레이션·자막 문구를 수정할 수 있다. |
| FR-03-3 | 장면별 이미지를 표시하고, 추출된 이미지 중 다른 것으로 변경할 수 있다. |
| FR-03-4 | 블로그 원본 이미지를 우선 사용한다. |
| FR-03-5 | 적절한 이미지가 없으면 대체 처리한다: 단색/그라데이션 배경 + 큰 자막 카드. |

### FR-04. TTS 및 자막

| ID | 요구사항 |
|---|---|
| FR-04-1 | 확정된 장면별 내레이션으로 음성을 생성한다. |
| FR-04-2 | 장면별 자막을 생성한다 (자막 문구를 화면 하단에 표시). |
| FR-04-3 | 장면 길이 = 해당 장면 TTS 오디오 길이(+짧은 여백)로 정해 음성과 장면을 동기화한다. |
| FR-04-4 | AI 생성 음성임을 결과 화면에 고지한다 (OpenAI 이용 정책). |

### FR-05. 영상 합성

| ID | 요구사항 |
|---|---|
| FR-05-1 | 9:16 세로형(1080×1920) 영상을 만든다. |
| FR-05-2 | 장면 이미지 + 음성 + 자막을 결합한다. |
| FR-05-3 | 총 길이 30~60초. 벗어나면 사용자에게 경고(문구 조정 유도)한다. |
| FR-05-4 | 출력 형식은 MP4(H.264 + AAC)다. |
| FR-05-5 | 합성은 백그라운드 작업으로 실행하고 진행 상태를 조회할 수 있다. |

### FR-06. 결과 확인

| ID | 요구사항 |
|---|---|
| FR-06-1 | 완성 영상을 브라우저에서 미리보기한다. |
| FR-06-2 | 영상 파일을 다운로드한다. |
| FR-06-3 | 생성 실패 시 실패 단계(TTS/합성 등)와 오류 메시지를 보여주고 재시도할 수 있다. |

## 6. 선택 기능 (MVP 이후)

| ID | 기능 | 비고 |
|---|---|---|
| OPT-01 | 장면별 AI 이미지 생성·재생성 | 이미지 생성 API 비용·시간 증가 |
| OPT-02 | TTS 음성 종류 선택 | OpenAI 내장 음성 목록 중 선택 |
| OPT-03 | 배경음악 적용 | 저작권 문제 없는 음원 필요, 볼륨 덕킹 |
| OPT-04 | 작업 내역 저장 | DB 도입 필요 → 현재 범위 밖 |

## 7. 비기능 요구사항

| ID | 항목 | 기준 |
|---|---|---|
| NFR-01 | 보안 | OpenAI API Key는 백엔드 환경변수로만 관리, 프론트엔드·저장소에 노출 금지 |
| NFR-02 | 보안 | 서버 측 URL 요청은 허용 목록 기반(SSRF 방지), 리다이렉트도 재검증 |
| NFR-03 | 성능 | 추출 ≤ 10초, 대본 생성 ≤ 30초, 영상 합성 ≤ 3분 (60초 영상 기준, 목표치) |
| NFR-04 | 안정성 | 외부 요청에 타임아웃·응답 크기 제한, 실패 시 일관된 오류 포맷 |
| NFR-05 | 사용성 | 각 단계에 로딩/오류 상태 표시, 오류 시 다음 행동 안내 |
| NFR-06 | 저장 | 생성 파일은 임시 저장 후 일정 시간(기본 24시간) 뒤 정리 |
| NFR-07 | 유지보수 | API는 OpenAPI(`/docs`)로 문서화, 요청/응답은 Pydantic 스키마로 정의 |
| NFR-08 | 호환성 | 최신 Chrome 기준, 데스크톱 우선 |

## 8. 기능별 완료 조건 (Acceptance Criteria)

**FR-01**
- [ ] `https://blog.naver.com/copper567/224443571088` 입력 시 제목·본문 텍스트·이미지 1개 이상이 반환된다.
- [ ] `m.blog.naver.com`, `PostView.naver?blogId=copper567&logNo=...` 형식도 같은 결과를 낸다.
- [ ] 다른 blogId, 다른 도메인, IP 주소 URL은 외부 요청 없이 `400 UNSUPPORTED_URL`로 거부된다.
- [ ] 존재하지 않는 글은 `422 EXTRACTION_FAILED`와 "본문을 직접 입력해 주세요" 안내를 표시한다.
- [ ] 본문 200자 미만 입력 시 제출 전에 검증 메시지가 표시된다.

**FR-02**
- [ ] 생성 결과는 스키마 검증을 통과한다: 장면 4~6개, 첫 장면 `hook`, 마지막 장면 `cta`, 나머지 `body`, `order`가 1부터 연속.
- [ ] 내레이션 총 글자 수가 목표 범위(약 150~350자) 안에 있다.
- [ ] OpenAI 오류·스키마 위반 시 `502 AI_GENERATION_FAILED`가 반환되고 화면에서 재시도할 수 있다.

**FR-03**
- [ ] 장면 문구를 수정하면 즉시 화면에 반영되고, 렌더 요청에 수정본이 사용된다.
- [ ] 이미지를 다른 추출 이미지로 바꿀 수 있다.
- [ ] 이미지가 없는 장면은 대체 배경으로 표시된다.

**FR-04 / FR-05**
- [ ] 결과 영상이 1080×1920, H.264/AAC MP4다 (`ffprobe`로 확인).
- [ ] 각 장면의 화면 전환 시점이 해당 장면 음성의 끝과 일치한다 (±0.3초).
- [ ] 각 장면의 자막 문구가 해당 구간에 표시된다.
- [ ] 렌더 요청은 즉시 `202`와 `job_id`를 반환하고, 상태가 `queued → running → succeeded|failed`로 바뀐다.

**FR-06**
- [ ] 성공 시 `<video>`로 재생되고, 다운로드 버튼으로 `.mp4` 파일을 받는다.
- [ ] 실패 시 실패 단계와 메시지가 표시되고 같은 장면 데이터로 재시도할 수 있다.
- [ ] 결과 화면에 "AI 생성 음성" 고지가 표시된다.

## 9. MVP에서 제외할 기능

- 로그인·회원·결제, 다중 사용자 작업 격리
- `copper567` 외 블로그 URL 추출, 티스토리·브런치 등 다른 플랫폼
- 타임라인 기반 세부 편집(컷 길이 수동 조정, 트랜지션 선택, 효과)
- 동영상 클립 소스, 배경음악, AI 이미지 생성 (선택 기능으로 분리)
- 작업 내역 DB 저장, 영상 SNS 자동 업로드
- 모바일 전용 UI 최적화

## 10. 외부 API 및 웹 콘텐츠 처리 시 주의사항

- **저작권·이용 허락**: 추출 대상은 `copper567` 블로그로 한정한다. 블로그 운영자의 사용 허락을 전제로 하며, 원본 글·이미지는 영상 제작 목적 외로 저장·배포하지 않는다.
- **네이버 이용약관·robots**: 대량·반복 수집을 하지 않는다. 사용자 요청 1건당 글 1개만 요청하고, 결과는 작업 단위로만 임시 보관한다.
- **구조 변경 위험**: 네이버 블로그 HTML(스마트에디터 ONE 구조)은 예고 없이 바뀔 수 있다. 추출 실패 시 본문 직접 입력으로 항상 진행 가능해야 한다.
- **이미지 신뢰**: 외부 이미지 URL을 그대로 신뢰하지 않는다. 허용 호스트(`*.pstatic.net`)만 다운로드하고, 크기·MIME·실제 이미지 디코딩을 검증한다.
- **OpenAI API**: 키는 백엔드만 보관한다. 요청 시간·비용 한도를 두고, 블로그 본문 외 개인정보를 보내지 않는다. 구조화 출력(JSON 스키마)으로 응답을 받고 Pydantic으로 다시 검증한다.
- **AI 음성 고지**: OpenAI TTS 이용 정책에 따라 결과물이 AI 생성 음성임을 사용자에게 알린다.
- **AI 결과 품질**: 생성 대본에 사실과 다른 내용이 섞일 수 있으므로, 사용자가 편집 단계에서 검토·수정하도록 안내한다.
